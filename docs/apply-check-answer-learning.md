# Check: Manager corrections and reusable answers

Auto Apply's review button is **Check**. It audits the form and automatically saves changed or newly answered fields. There is no proposal or Super Admin approval step. Automatic navigation/checklist refreshes do not save answers.

The extension takes a baseline after filling each step and compares Check's snapshot with it. Unchanged AI/site/profile answers are not learned again. Explicit checkbox deselections are changes; blank clears never erase a saved answer. Passwords, verification codes, CAPTCHA and files are excluded. Successful fields advance the persisted baseline; failures remain retryable on the next Check. Fill again resets the baseline after filling so QTS's own changes are not mistaken for Manager corrections.

## Ownership and scope

`manager_apply_answers` is separate from the global `reusable_answers` library. Every extension save requires the authenticated Manager, identified Chrome, a live held attempt, an unblocked candidate owned by that Manager, and a valid lease. Candidate/job IDs come from the attempt, never from the request body.

* Candidate facts are reusable only for that candidate. Unambiguous city, first/last name, email, phone and LinkedIn corrections also update the profile in the same database batch. Current profile values remain authoritative after later profile edits. Salary expectations, availability, notice, relocation, work authorization, sponsorship, work arrangements and employer/role facts are also candidate-specific or contextual; they cannot be learned into or written to the global library.
* Recognized shared questions, including application source, save directly to the Manager's library. Legal consent, privacy terms and attestations are application-scoped because their wording and consequences are employer-specific. Unknown or country/company/job-dependent questions save automatically for this candidate/job and are displayed as contextual/uncertain. A shareable uncertain entry can be moved immediately to the Manager's reusable library from Saved changes or My profile. Personal facts cannot be broadened across candidates.
* The global library is reserved for answers genuinely shared across candidates. Super Admin saves, Manager proposals, approvals and history restores all reject candidate-specific or application-specific questions. Legacy global rows with either scope remain visible for administration but are filtered out before an application receives its answers.
* For a matching shared question, a current application/candidate correction is the most specific answer, then the eligible global answer, then the Manager-wide fallback. Global answers take priority over Manager answers only; they do not overwrite a current application exception. Publishing does not rewrite answers already filled in an active application.

My profile lists saved scopes, candidate names, wording variants, edit/delete controls and direct additions. Deleting a saved contact correction does not erase the candidate's profile fact. Super Admin can publish shared Manager answers globally from Settings. The original Manager answer is retained and becomes the fallback when that global answer is removed. Historical draft review remains for earlier drafts/learning suggestions; Check never creates a draft.

## Wording variants

Store the question, selected answer, field kind and offered choices. Manager, candidate and application answers match by normalized question identity, with recognized aliases for application source; their variants preserve the offered choices and field kind. The global library can also match by exact question and, in Auto Apply, a conservative meaningful-word overlap. This is not general semantic equivalence: a new paraphrase is not guaranteed to match, and overlapping words alone do not prove the same intent. A text answer `LinkedIn` and choice `LinkedIn Job Post` may coexist as equivalent variants. `LinkedIn Recruiter` is a different meaning. A dropdown must use a real offered option; Manager-scoped answers with an ambiguous or nonmatching option are left for the Manager rather than forced to another choice.

Matching is conservative, not a general semantic-equivalence guarantee. Contextual answers are currently restricted to their original job rather than inferred across countries or employers. A Manager can deliberately broaden a shareable answer. Unchanged prefilled answers are not automatically added to the library.

## Release and verification

Apply migrations `0081_manager_apply_answers.sql`, `0082_manager_chatgpt_url.sql`, `0083_auto_apply_claim_scope.sql`, and `0084_manager_auto_apply_parallel_limit.sql` with the normal migration process **before** deploying this server release. Deploy the matching server and reload the rebuilt extension. Database configuration is unchanged. No production migration is performed by the tests.

The same migration adds `profiles.manager_category`: an optional Manager-written label, initially empty for all candidates. The Manager's create/edit forms accept free text (80 characters maximum), without selecting from the Super Admin category catalog. Editing this label does not change the existing global `category_id`. Candidate selectors show `Name (Label)` when a label is present, and only the name when empty.

Generation and Auto Apply job pickers filter locally by title, full URL or company, ignoring case. Filtering preserves checked jobs and explicitly reports selected jobs hidden by the filter. Select all acts on the visible results. Searching does not fetch again or modify jobs.

Auto Apply runs up to the Manager's configured number of applications per Chrome (default 2; 1–10); a later job waits until a slot is free. Selecting a profile always runs its chosen jobs one at a time. Each job has its own checklist, correction baseline, fill-attempt report and review tab. Unanswered form questions, including personal-fact questions, are sent to the configured AI prompt; the extension checks response format and field constraints, then the Manager reviews the filled answers before submission. A bounded correction request is made for unusable or site-rejected answers; if the AI still cannot answer, Auto Apply reports that explicitly for the Manager. Sign-in, registration, one-time codes, and CAPTCHA remain human-controlled: QTS can fill supported non-secret profile fields, but does not type passwords/codes or bypass human checks. When an application opens in a new tab, Auto Apply follows it and closes the source job tab. Cancel, closing the application tab, or restarting Chrome releases unfinished claims but retains their last checkpoint. A later claim for that job reopens the form and reuses saved answers, checklist state, and progress; it cannot restore the site's closed DOM or the exact live form session. Successfully submitted jobs remain on the Manager's confirmation step and are never replayed. Jobs with a live claim in another Chrome remain visible but unchecked and disabled. Auto Apply requires an active assigned account, a résumé, no existing bid, and at least three experience entries; Managers assigned Gemini Get JD additionally need matching notes. Prior failed, skipped, or released attempts do not by themselves exclude a job.

Managers assigned Custom URLs access from Get JD can add domain prefixes in the extension's Tools → Custom URLs panel. Without an explicit candidate/job selection, Auto Apply skips matching domains; the jobs remain selectable. Explicitly selected matching jobs use Gemini for AI answers for that application, regardless of the Manager's usual provider assignment. A prefix such as `djni.co` matches that domain and its subdomains, not unrelated domains containing the same text.

After the Manager confirms successful Auto Apply submission, QTS records the bid and deletes the job row in the same database batch. If confirmation is negative, the job is retained as failed; if the tab or browser closes before confirmation, the pending confirmation stays on the Jobs page and is not replayed.

Auto Apply normally uses ChatGPT regardless of the Manager's Super Admin provider assignment. The explicitly selected Custom URL jobs described above use Gemini instead. ChatGPT starts each application in the Manager's configured ChatGPT Project URL, or `https://chatgpt.com/` when no URL is configured. Debug-only no-AI mode remains available for synthetic tests. AI turns are serialized one application at a time while other open forms can still fill profile and reusable answers. ChatGPT starts one fresh conversation per application; follow-up turns for that application reuse its conversation, and the extension replaces the tab after 10 applications.

Each Manager can set their own HTTPS ChatGPT Project URL in their QTS Settings page. ChatGPT-backed Apply opens a fresh chat from that URL for each application and replaces its pinned tab after ten applications; Generation uses the same setting and rotation limit.

Server tests cover parsing, scope, variants, save failures, query ownership constraints and service writes using fixtures. Real Chrome tests exercise the actual extension against a localhost mock server and synthetic forms. They do not submit real applications, call live AI or access production records. Database integration still requires a separate non-production Postgres environment; mocked tests do not establish production migration success.
